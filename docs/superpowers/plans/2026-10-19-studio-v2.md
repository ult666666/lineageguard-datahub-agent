# LineageGuard Studio 2.0 Implementation Plan

> Execute inline with test-driven development and whole-branch verification. The owner explicitly delegated design and deployment-review details in the approval turn.

**Goal:** Ship a working, inspectable data-change orchestration studio and durable local runtime.
**Architecture:** Shared browser/Node DAG interpreter and policy modules; typed synthetic and optional read-only MCP adapters; a SQLite local run service; a browser-session public preview. Preserve the classic demo and its APIs.
**Tech Stack:** Node 22.13+/24, native Web Crypto, SQLite, vanilla ES modules, node:test, Playwright.
**Spec:** ../specs/2026-10-19-studio-v2.md

## Global constraints

No paid inference, catalog mutation or SQL execution. No private source/runtime/account data in public artifacts. Node runtime dependencies remain zero. Cloud preview does not claim durable execution or authenticated approvals. Source content and checkpoints have bounded sizes; arbitrary code and arbitrary network destinations are not accepted. Existing classic API compatibility is tested.

## Review focus

Partial evidence, request/response identity mismatch, cancellation racing a late tool result, stale writers after lease takeover, and a modified request retaining an old result/acknowledgement.
