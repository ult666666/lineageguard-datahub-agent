Architecture

A review is a small workflow graph. Studio compiles it, runs the evidence reads with limits, and applies a fixed policy. The browser and the local service run the same modules.

Compile the graph

Unknown steps, cycles, missing dependencies and budgets over the limits are refused before the first read. A generated recipe gets no extra privileges.

core/recipe.js

Run with limits

Reads run concurrently with retries, deadlines and cancellation. Each state change is checkpointed, with hash-linked events, before the run continues.

core/runtime.js

Keep risk and evidence apart

Numeric narrowing is blocked even within one type family. Missing usage, partial lineage and stale observations keep a review from being ready.

core/policy.js

Fence stale writers

The local service stores runs in SQLite with revision compare-and-swap and expiring writer leases. A run left by a stopped process can resume once its lease expires.

src/studio/store.mjs

Runtimes

Browser session

The hosted demo. The workflow runs in your browser against same-origin synthetic reads, and checkpoints stay in browser storage. Export a run to keep a copy.

Local service

npm run studio:local adds a loopback API, SQLite checkpoints and writer leases. The optional DataHub client uses MCP protocol version 2025-11-25.
